# DISHA session evidence Android component

This is a native component source drop for the DISHA Android host application. The repository does not currently contain a complete installable Android application module, so this source is not yet a buildable APK.

## Behaviour
- Requires the payer to explicitly enable Android Notification Access in system settings.
- Enrols a P-256 key in Android Keystore for each active checkout session.
- Keeps multiple enrolled devices on the same server session nonce; pairing another device does not rotate the nonce.
- Processes notifications only from package IDs allowlisted by the server and only while a session is active and unexpired.
- Extracts only a candidate amount, payee VPA, labelled transaction reference and status. It never uploads full notification text or unrelated notifications.
- Signs the canonical event using the Android Keystore key and sends it to /api/session-evidence/event.
- Clears the local session with stopSession(context) when checkout ends or the user revokes consent.

## Host integration
1. Add SessionEvidenceNotificationListener.java to an Android application module with package namespace com.disha.evidence.
2. Merge the AndroidManifest.xml service declaration into that host app's manifest.
3. After the checkout's explicit consent action, invoke openNotificationAccessSettings(context) only if Android Notification Access is not enabled. Do not show the permission screen on every checkout.
4. After returning from system settings and confirming access is enabled, call enroll(context, apiBase, orderId, sessionToken, deviceId). Use a stable random device ID generated by the host app; never use an advertising ID.
5. On checkout end, expiry or explicit revocation call stopSession(context).

## Integration constraints
- Android Notification Access is a broad OS permission. DISHA filters before transmission; the OS permission itself is not scoped to a single checkout.
- Notification formats vary by app, language and version. Amount/VPA/reference fields may be absent or ambiguous. Missing values remain null; never infer them.
- Server decisions remain INCOMPLETE_SIGNAL unless amount, payee and reference all match the active session.
- The P-256 signature authenticates the enrolled device key. It does not provide hardware attestation or protect against a compromised OS.
- The repository currently has no Gradle host app to compile this component. Test Android API compatibility and actual GPay/PhonePe notification formats on physical devices before release.
